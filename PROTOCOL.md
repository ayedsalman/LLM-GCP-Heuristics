# Protocol freeze (revision plan S0.5)

This file fixes every decision that could be tuned after seeing test
results. It is committed, together with `registry/datasets.lock.json` and
`registry/protocol_freeze.json`, **before** any heuristic is evaluated on
TEST-A, TEST-B, PLANTED or DIMACS. Changing any line below after a TEST
evaluation requires a new, dated section that explains why. The test numbers
obtained under the old rule must still be reported.

## 1. Data roles

| Set | Role | Used for |
|---|---|---|
| VAL | development | candidate selection, refinement failure instances, tuning of controls (CMA-ES, grid), perturbation study |
| TEST-A | primary test | every headline number; same design as Table 4 of the submission |
| TEST-B | balanced test | per-family/per-scale claims; mean degree matched across families (R1.1) |
| PLANTED | ground truth | exact optimality gaps (chi = k by construction) |
| DIMACS | external | community-standard instances; gaps to published bounds (bounds.csv carries source and date) |

No TEST/EXT instance is shown to an LLM, used for selection, or used to
tune any coefficient.

## 2. Selection rule (A3)

For each model and each generation seed, among the candidates that pass the
AST validator, select the one with the

1. lowest mean colour count on VAL (all 140 instances, equally weighted);
2. ties: lower median VAL runtime of the incremental evaluator;
3. ties: lower candidate index in the response.

The same rule selects after each refinement round and in the control arms
(best-of-5 per draw).

## 3. Generation and refinement (B1, B4, B5)

* Models: GPT-4o, GPT-5.1, Claude 3.5 Sonnet, DeepSeek-V3, LLaMA 3.1 70B.
  The exact snapshot ID returned by each API is recorded per query. If a
  snapshot has been retired, the closest available one is used and the change
  is reported.
* Prompt: the universal prompt of Figure 4, verbatim
  (`src/gcpbench/llm/prompts.py`). Temperature 0.7, no system prompt.
* Seeds: N = 20 independent queries per model (minimum 10). A 5-seed pilot
  may increase N, never decrease it below 10; the pilot's SD and the
  resulting N are recorded here before the main run.
* Validator: strict linearity (C1). On violation the model is re-queried
  with the same prompt, at most 3 times; every rejection is logged.
* Refinement: exactly 2 rounds for every model, seed and arm
  (T targeted / G generic / R random-VAL / N resample). Failure instances
  come from VAL only. The structural explanation is generated by
  `src/gcpbench/llm/explain.py`; no author-written text enters the loop.
* Optional temperature-0 arm: 5 seeds per model.

## 4. Controls (B2, B3)

* R-U: 20 draws x 5 candidates, coefficients iid Uniform[-1, 1]^5; best of 5 on VAL.
* R-D: 20 draws x 5 candidates, Dirichlet(1,1,1,1,1) weights; best of 5 on VAL.
* Handcrafted: sat only; lexicographic DSATUR (sat, deg); sat + 0.01*ucn;
  7 x 7 grid over (w_sat, w_deg) in {0, 0.01, 0.1, 0.5, 1, 2, 10} with the other weights 0.
* Tuned: CMA-ES over the five coefficients on VAL, 20 restarts, about 500
  evaluations per restart, sigma0 = 0.5 on standardised coefficients.
  The evaluation engine is `gcpbench.fastlinear`.

## 5. Statistics (Section 2.3 of the plan; `src/gcpbench/stats.py`)

* Unit: instance (paired across heuristics) within family x scale strata;
  seed is the unit when comparing models.
* Primary: paired difference vs DSATUR (the paper's `sat*10000 + deg`),
  mean with 95% bootstrap CI (10,000 resamples, seed 0), Wilcoxon signed-rank
  (Pratt zeros), Holm correction across all heuristic-vs-DSATUR comparisons
  of a table.
* Equivalence: TOST, margin **delta = 0.10 colours**, alpha = 0.05. The words
  "matches" and "indistinguishable" are used only for TOST-equivalent
  results.
* Friedman/Nemenyi kept for continuity, on TEST sets only; q_alpha from the
  studentized range distribution. Every test is listed with N, k, chi^2,
  df, p and CD.
* Across seeds: mean, SD and 95% bootstrap CI of per-seed TEST means;
  Kruskal-Wallis, then Holm-corrected Mann-Whitney with Cliff's delta.
* Every headline result is reported pooled **and** per family x scale.

## 6. Hypotheses and decision thresholds

* H-A (selection optimism, E-A): optimism = (VAL - TEST mean) of the selected
  heuristic minus the same for DSATUR. If its 95% CI excludes 0, the TEST
  numbers replace the VAL numbers in the abstract.
* H-B (LLM contribution, E-B2): an LLM arm "adds value" only if its TEST
  mean is lower than the R-U and R-D arms with Holm-adjusted p < 0.05
  across seeds.
* H-B3 (feedback, E-B3): targeted feedback helps only if T beats G, R and N
  in the paired refined-minus-parent difference with Holm p < 0.05.
* H-F (kernel sensitivity, E-F): if the anti-priority controls (-deg, -sat)
  give the same colour counts as the LLM priorities on > 90% of
  instances, the kernel is declared priority-insensitive and investigated
  before any GPU claim is made.
* H-E (runtime, E-E): a practical-speed claim requires the median
  equal-footing runtime ratio to DSATUR to be <= 1.5.

## 7. Implementation constants

* Tie-break: lowest vertex id, for every sequential heuristic and for the
  local-maxima rule of the parallel kernel.
* Parallel rand(): a per-vertex hash `splitmix64(seed XOR v)` mapped to
  [0, 1), fixed for the whole run (Jones-Plassmann convention). Seeds 0..9
  are reported as variance over runs (C5).
* Timing: >= 30 repetitions after 3 warm-ups, median and IQR, one pinned
  core, single-threaded BLAS; GPU timings repeated on >= 2 sessions.
* Exact chi: CP-SAT, 60 s per small instance; LB = clique number,
  UB = best of 5 TabuCol runs (300 s medium, 900 s large).

## 8. Discipline rule

Once TEST-A, TEST-B and the EXT sets are evaluated, selection rules,
equivalence margins and hypotheses are not changed. Unwelcome results are
reported and the claims are adjusted, not the protocol.
